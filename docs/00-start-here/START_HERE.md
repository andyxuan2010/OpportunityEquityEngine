# Start Here: Your First Contribution

This is the shortest path from “I want to help” to a useful, reviewable contribution. You do not need to know everything before you begin.

## The project in one minute

The Opportunity Equity Engine helps high school students discover, understand, and prioritize meaningful opportunities. We are building a small, trustworthy vertical slice first:

```text
student profile → verified opportunity data → match → explanation → next step
```

## Your first 60 minutes

1. Read the [documentation index](../INDEX.html) and the [beginner project guide](../03-student-guides/BEGINNER_PROJECT_GUIDE.html).
2. Choose one role for your first task: researcher, product designer, developer, tester, data reviewer, or presenter.
3. Read the [learning prerequisites](../03-student-guides/LEARNING_PREREQUISITES.html) and the [student toolkit](../08-student-toolkit/STUDENT_TOOLKIT.html).
4. Set up Git, your editor, and the tools described in the [implementation guide](../05-build/DEMO_IMPLEMENTATION_GUIDE.html).
5. Open one GitHub issue that describes a small outcome, not a vague activity.
6. Make one small change, test it, and record what you learned in the issue or pull request.

## Working agreement

- Make the smallest useful change first.
- Ask for clarification in writing when a requirement is unclear.
- Treat AI output as a draft; understand, test, and review it before using it.
- Never commit passwords, API keys, private student information, or copied work without permission.
- Cite sources and mark sample data, assumptions, and future ideas clearly.
- Give feedback about the work, not about the person.

## Definition of ready

Before starting, you can answer: Who benefits? What will change? What is out of scope? How will we test it? What evidence or source supports the decision?

## Definition of done

- The change works on the intended screen or document.
- A beginner can follow the instructions or reproduce the result.
- Tests, screenshots, source links, or review notes are included when relevant.
- Accessibility, privacy, and security risks were considered.
- Another teammate reviewed the result, or the issue explains why review is pending.

## When you are stuck

Spend 15 minutes trying to understand the error. Copy the exact message, describe what you expected, list what you tried, and ask one focused question in the issue. A clear question is a contribution because it makes the next attempt easier for everyone.
