# 面向高中生的 Vibe Coding

## 你不必害怕编程

Vibe Coding 是一种用自然语言描述目标、让 AI 协助生成小段代码、运行结果、阅读错误并持续改进的工作方式。它降低了开始编程的门槛，但不会替你做产品判断。

## 一个好的循环

```text
描述一个小目标 → 生成代码 → 运行 → 观察 → 提问为什么 → 修改 → 测试
```

一次只改变一个小行为。让 AI 说明修改了什么、为什么这样修改、可能失败在哪里，并要求它提供可检查的测试。

## Vibe Coding 擅长什么

当你知道想实现什么，但还不熟悉语法或框架时，Vibe Coding 很有帮助：

| 适合的用途 | 示例请求 | 你仍然要做什么 |
|---|---|---|
| 创建界面草稿 | “创建一个适合手机的机会卡片，显示标题、截止日期、费用、来源和保存按钮。” | 决定学生真正需要的信息，并检查手机布局。 |
| 设计数据结构 | “建议一个机会的 JSON 结构并解释字段。” | 决定必要字段，并根据官方来源核验。 |
| 探索匹配规则 | “编写函数，匹配学生年级和机会的最低、最高年级。” | 定义边界、测试结果并检查公平性。 |
| 理解错误 | “用初学者语言解释错误，找出可能文件，并给最小安全修复。” | 复现、应用修复并检查其他影响。 |
| 编写测试和文档 | “为无结果、已过期和匹配成功写测试。” | 阅读每个测试，确认它代表真实行为。 |

AI 不擅长决定学生真正需要什么、确认截止日期是否最新、保护隐私或判断产品是否公平安全。这些责任仍属于团队。

## 三个具体例子

### 例子一：从用户故事到页面

```text
我是一名喜欢生物的十年级学生，想看到仍可申请的机会，并理解它为何适合我。
请只创建第一个页面：三个机会卡片，显示名称、类别、截止日期、费用、匹配理由和官方来源。
只使用样例数据，支持键盘，并在 390px 宽手机上可读。暂时不要加入登录或数据库，解释每个文件。
```

运行后调整浏览器宽度，并请同学找出一个相关机会。如果他不知道为什么出现这个结果，应先改进文字或数据，而不是只改颜色。

### 例子二：从政策到测试规则

如果团队规定学生年级在机会的最低和最高年级之间（包括边界）才算符合，可以要求 AI 生成小函数和测试：低于最低、刚好最低、范围内、刚好最高、高于最高及缺失数据。你决定“包括边界”是否正确，审查代码并运行测试；AI 只负责表达规则，不能替团队制定政策。

### 例子三：从错误到学习循环

把准确错误信息、网络响应和最小相关代码交给 AI，让它用初学者语言解释数据流、提出两个可能原因，并一次给出一个诊断步骤。这样你能判断问题来自请求、数据、筛选还是显示，而不是接受一次无法解释的大改写。

## 好用的提示词结构

```text
背景：我们为手机上的学生机会搜索器开发功能。
目标：给搜索页面加入“没有结果”的提示。
限制：保持现有视觉风格，不修改 API 或翻译。
验证：列出改动文件，并提供包含无结果情况的两个测试。
```

好的提示词包含背景、小目标、限制和验证方式。如果你无法解释改了什么，就不应合并。

## 保持创造力和责任

学生仍然是产品负责人、设计师、研究员、测试者和决策者。AI 不是来源，也不能决定哪些信息真实。任何机会的名称、费用、资格、截止日期和结果都必须回到官方资料核验。

## 常见错误

- 一次要求 AI 建造整个应用。
- 复制代码却不运行、不阅读。
- 把看似合理的 AI 输出当成事实。
- 没有保存小步提交，导致无法回退。
- 只关注界面而忽略数据、隐私和错误状态。

## 最佳实践

从一个可演示的小功能开始，保留问题和解决方案记录，提交可理解的版本，邀请同伴测试，并把学到的概念写回项目文档。
