# 机会公平引擎——快速构建应用和网站指南

本指南说明学生如何快速把一个小想法变成可运行的网站、适合手机使用的 Web 应用或早期 iPhone 原型。目标不是一次完成所有功能，而是先完成一条有用的流程，让真实用户测试，再持续改进。

## 选择最小的有用路径

| 你想制作的内容 | 快速起步路径 | 可以展示的内容 |
|---|---|---|
| 公共网站 | HTML、CSS 和 JavaScript | 有真实内容和链接的精致页面 |
| 适合手机的应用 | 响应式网站或 PWA | 在手机浏览器中具有应用感的体验 |
| iPhone 原型 | Xcode 中的 SwiftUI 或 Expo | 几个页面和一个可运行的交互 |
| 使用数据的演示 | 网站加简单 API 或托管数据库 | 搜索、筛选、保存或推荐 |

选择能让团队最快测试想法的路径。响应式网站通常是最好的第一版，因为它可以在电脑和手机上运行，不需要等待应用商店发布。

## 最快的网站路径

第一版可以先创建三个小文件：

```text
my-project/
├── index.html
├── style.css
└── app.js
```

使用 `index.html` 编写结构，使用 `style.css` 设计外观，使用 `app.js` 编写交互。可以让 AI 编程助手一次创建一个小功能，然后在浏览器中打开页面并自己测试。

适合作为第一步的功能包括：

- 用搜索框筛选机会列表。
- 收集年级、兴趣、地点和预算的表单。
- 解释某个机会为什么可能适合用户的结果卡片。
- 在浏览器中保存短列表的按钮。
- 打开原始来源的清晰“申请”链接。

可以使用 GitHub Pages 或其他静态托管服务发布网站。只有当页面和用户流程已经通过样例数据验证后，再添加真实数据。

## 让网站像手机应用一样好用

在构建原生应用前，先让网站适合小屏幕：

1. 在宽度低于约 700 像素时使用单列布局。
2. 让按钮和表单字段容易点击。
3. 把重要操作放在屏幕下方容易找到的位置。
4. 用真实手机测试，而不只是缩小桌面浏览器窗口。
5. 只有基础体验稳定后，再添加 Web App manifest 和图标。

适合手机的网站可以通过链接分享，也可以添加到手机主屏幕。这是很有用的产品演示方式，因为学生可以马上和同学测试体验。

## 三条实用的 iPhone 路径

### SwiftUI 和 Xcode

当团队想学习 Apple 原生工具并构建 iPhone 专属原型时，可以使用 SwiftUI。先设计少量页面并使用样例数据，之后再连接真实服务。原生 iPhone 开发通常需要在 Mac 上使用 Xcode，因此要先确认团队可以使用所需硬件并完成 Apple 开发者设置。

### Expo 和 React Native

当团队已经了解 JavaScript，或希望一套代码逐步支持多个移动平台时，可以使用 Expo。学生可以从一个小页面、一个列表和一个交互开始。第一版应避免复杂的身份验证、支付或后台服务。

### 渐进式 Web 应用

当重点是速度、可访问性和易于分享时，可以使用响应式网站。PWA 可以提供类似应用的外壳，同时保持部署简单。对本项目的第一版学生演示来说，这通常是最实际的选择。

## 60 分钟构建计划

1. **选择一个用户：** 例如，正在寻找低成本暑期项目的 11 年级学生。
2. **选择一个动作：** 搜索、筛选、比较或保存机会。
3. **画出三个页面：** 开始页、结果页和详情页。
4. **创建样例数据：** 先用五条可信的记录，并明确标记为样例。
5. **完成主要流程：** 先让一条完整的交互运行，再增加选项。
6. **请两个人测试：** 观察他们在哪里犹豫，并记录问题。
7. **修复最大的问题：** 先提升清晰度，再增加新功能。

## 有用的 AI 编程提示词

向助手提供明确的请求、背景、限制和测试方法：

```text
使用纯 HTML、CSS 和 JavaScript 构建一个响应式机会搜索页面。
在数组中加入五个样例机会，并添加年级和费用筛选器。
不要使用框架或后端。让布局在手机上可访问。
完成后说明如何测试筛选器，以及哪些文件发生了变化。
```

然后一次只要求一个改动：“添加空状态”“解释这个函数”或“让按钮支持键盘操作”。检查每个改动并测试后，再提出下一项请求。

## 小型项目示例

- **机会查找器：** 筛选五个样例项目，并解释每个匹配结果。
- **申请计划器：** 将截止日期变成带状态标签的清单。
- **学生资源地图：** 按地点和类别展示资源。
- **团队展示页：** 展示问题、原型、证据和下一步。

每个示例都足以完成第一版演示。一个令人信服的小流程，比一个页面很多但没有完成的应用更好。

## 分享前的测试

- 在窄手机屏幕和宽屏上检查页面。
- 使用键盘访问每一个控件。
- 测试空搜索和无效表单值。
- 确认链接打开正确的来源。
- 不要把 API 密钥、密码或学生隐私信息放在浏览器代码中。
- 诚实标记样例记录、AI 生成内容和未来功能。
- 请没有参与构建页面的学生完成主要任务。

## 学生真正负责的内容

AI 可以建议代码、布局、测试案例和解释。学生仍然负责选择问题、保证数据质量、做出隐私决定、进行视觉表达、测试，以及决定哪些内容可以展示。快速构建的同时，要保持项目足够易懂，让每位队员都能解释它。

## 本项目的推荐路径

先使用样例机会数据构建响应式静态网站。加入筛选、清晰的推荐解释和来源链接。当这条流程可以在手机上正常运行后，再决定简单 API、托管数据库、PWA 安装提示或原生 iPhone 原型是否值得增加复杂度。
