# Opportunity Equity Engine — Beginner Demo Implementation

This guide shows how a small team of high school students can build a working demo from zero. It is intentionally small: the goal is to prove the complete user journey before adding advanced crawling, authentication, vector search, or a large AI system.

## What the demo will do

```text
Student enters grade, location, interests, and budget
              ↓
Application loads verified demo opportunities
              ↓
Deterministic rules remove obvious ineligible items
              ↓
Simple scoring ranks the remaining opportunities
              ↓
Student sees a score, reason, deadline, and source link
```

The first demo should answer one question:

> Can a Grade 11 student in Montreal discover a few relevant opportunities and understand why they were recommended?

## Recommended beginner architecture

For the first demo, keep the architecture simple:

```text
Next.js web app
    ├── Pages and components
    ├── API route for recommendations
    ├── Eligibility and ranking code
    └── Supabase client
              ↓
        Supabase PostgreSQL
              ↓
        Opportunity records
```

A separate FastAPI service can be introduced later. It is not needed to prove the first user journey.

## Step 0 — Agree on the smallest demo

Write this in a GitHub Issue before coding:

### Demo user story

> As a Grade 11 student in Montreal interested in AI, I want to see opportunities that fit my grade, location, interests, and budget, together with a clear reason and a source link.

### Demo acceptance criteria

- A student can enter a grade, location, interest, and maximum budget.
- The app displays at least three sample opportunities.
- Grade and location rules work.
- Results are sorted by a visible match score.
- Each result shows a deadline, reason, and source URL.
- The app has loading, empty, and error states.
- The demo uses fictional or manually verified records and clearly labels them.

Do not add login, automated scraping, chat, or a mobile app until this flow works.

## Step 2 — Create the database

Create a Supabase project and open its SQL Editor. Start with one table. Do not design the entire future database yet.

Run this SQL:

```sql
create table opportunities (
  id bigint generated by default as identity primary key,
  title text not null,
  organization text not null,
  description text not null,
  category text not null,
  min_grade integer not null default 9,
  max_grade integer not null default 12,
  locations text[] not null default '{}',
  interests text[] not null default '{}',
  languages text[] not null default '{English}',
  cost numeric not null default 0,
  deadline date,
  application_url text not null,
  source_url text not null,
  verified_at date not null default current_date,
  published boolean not null default true,
  created_at timestamptz not null default now()
);

alter table opportunities enable row level security;

create policy "published opportunities are publicly readable"
on opportunities for select
to anon, authenticated
using (published = true);
```

### Why these fields exist

| Field | Purpose |
|---|---|
| `min_grade`, `max_grade` | Deterministic grade eligibility |
| `locations` | Location matching without an exact address |
| `interests` | Simple interest matching before embeddings |
| `cost` | Budget filtering |
| `deadline` | Deadline display and urgency scoring |
| `source_url` | Evidence and user verification |
| `verified_at` | Data freshness |
| `published` | Hide records without deleting them |

The public read policy is acceptable for fictional demo records. Before collecting real student profiles or adding admin writes, review Row Level Security policies carefully and keep write operations server-side.

## Step 4 — Connect Next.js to Supabase

Install the client library inside `web`:

```bash
npm install @supabase/supabase-js
```

Create `web/.env.local`:

```text
NEXT_PUBLIC_SUPABASE_URL=your-project-url
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=your-publishable-key
```

Do not commit `.env.local`. Confirm that `.gitignore` includes it.

Create `web/lib/supabase.ts`:

```ts
import { createClient } from "@supabase/supabase-js";

export function getSupabaseClient() {
  return createClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY!,
  );
}
```

For a more complete authenticated application, use the server and browser client pattern from the official Supabase Next.js guide. Do not use a Supabase service-role key in browser code.

## Step 6 — Build deterministic matching logic

Create `web/lib/matching.ts`:

```ts
import { MatchResult, Opportunity, StudentProfile } from "./types";

function normalize(value: string) {
  return value.trim().toLowerCase();
}

export function scoreOpportunity(
  student: StudentProfile,
  opportunity: Opportunity,
): MatchResult {
  const reasons: string[] = [];
  const blockers: string[] = [];

  const gradeMatches =
    student.grade >= opportunity.min_grade &&
    student.grade <= opportunity.max_grade;

  if (gradeMatches) {
    reasons.push("Your grade is within the program range.");
  } else {
    blockers.push(
      `This opportunity is for grades ${opportunity.min_grade}–${opportunity.max_grade}.`,
    );
  }

  const locationMatches = opportunity.locations.some(
    (location) =>
      normalize(location) === normalize(student.location) ||
      normalize(location) === "online",
  );

  if (locationMatches) {
    reasons.push("The location works for you or the opportunity is online.");
  } else {
    blockers.push("The listed location does not match your profile.");
  }

  const budgetMatches = opportunity.cost <= student.maxBudget;
  if (budgetMatches) {
    reasons.push("The listed cost is within your budget.");
  } else {
    blockers.push("The listed cost is above your budget.");
  }

  const interestMatches = student.interests.filter((studentInterest) =>
    opportunity.interests.some(
      (opportunityInterest) =>
        normalize(opportunityInterest).includes(normalize(studentInterest)) ||
        normalize(studentInterest).includes(normalize(opportunityInterest)),
    ),
  );

  if (interestMatches.length > 0) {
    reasons.push(`Interest match: ${interestMatches.join(", ")}.`);
  }

  // Hard requirements are handled by code, not by an LLM.
  const eligible = gradeMatches && locationMatches && budgetMatches;

  if (!eligible) {
    return { opportunity, eligible, score: 0, reasons, blockers };
  }

  const score = Math.min(
    100,
    40 +
      Math.min(20, interestMatches.length * 10) +
      (locationMatches ? 10 : 0) +
      (budgetMatches ? 10 : 0) +
      (opportunity.deadline ? 5 : 0),
  );

  return { opportunity, eligible, score, reasons, blockers };
}
```

### Important design rule

The matching function must be predictable. Given the same student and opportunity, it should return the same result every time. Write tests for it before adding AI explanations.

## Step 7 — Add a recommendation API route

Create `web/app/api/recommendations/route.ts`:

```ts
import { NextResponse } from "next/server";
import { getSupabaseClient } from "@/lib/supabase";
import { scoreOpportunity } from "@/lib/matching";
import { StudentProfile } from "@/lib/types";

export async function POST(request: Request) {
  try {
    const student = (await request.json()) as StudentProfile;

    if (
      !Number.isInteger(student.grade) ||
      student.grade < 7 ||
      student.grade > 13 ||
      !student.location ||
      !Array.isArray(student.interests) ||
      typeof student.maxBudget !== "number"
    ) {
      return NextResponse.json(
        { error: "Please provide a valid student profile." },
        { status: 400 },
      );
    }

    const supabase = getSupabaseClient();
    const { data, error } = await supabase
      .from("opportunities")
      .select("*")
      .eq("published", true);

    if (error) {
      console.error("Opportunity query failed", error);
      return NextResponse.json(
        { error: "Could not load opportunities." },
        { status: 500 },
      );
    }

    const results = (data ?? [])
      .map((opportunity) => scoreOpportunity(student, opportunity))
      .filter((result) => result.eligible)
      .sort((a, b) => b.score - a.score);

    return NextResponse.json({ results });
  } catch (error) {
    console.error("Recommendation request failed", error);
    return NextResponse.json(
      { error: "The recommendation request could not be completed." },
      { status: 500 },
    );
  }
}
```

Ask the AI assistant to explain each block. Do not accept code that the team cannot explain at a high level.

## Step 8 — Build the student profile page

Create a simple client component in `web/app/page.tsx`. The first version can keep the profile in browser memory and send it only when the student clicks the recommendation button.

```tsx
"use client";

import { FormEvent, useState } from "react";

type Result = {
  opportunity: {
    id: number;
    title: string;
    organization: string;
    description: string;
    category: string;
    deadline: string | null;
    cost: number;
    application_url: string;
    source_url: string;
    verified_at: string;
  };
  score: number;
  reasons: string[];
};

export default function HomePage() {
  const [grade, setGrade] = useState("11");
  const [location, setLocation] = useState("Montreal");
  const [interests, setInterests] = useState("AI, medicine");
  const [maxBudget, setMaxBudget] = useState("300");
  const [results, setResults] = useState<Result[]>([]);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState("");

  async function getRecommendations(event: FormEvent<HTMLFormElement>) {
    event.preventDefault();
    setLoading(true);
    setError("");

    try {
      const response = await fetch("/api/recommendations", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({
          grade: Number(grade),
          location,
          interests: interests
            .split(",")
            .map((item) => item.trim())
            .filter(Boolean),
          maxBudget: Number(maxBudget),
          language: "English",
        }),
      });

      const body = await response.json();
      if (!response.ok) throw new Error(body.error ?? "Request failed");
      setResults(body.results);
    } catch (requestError) {
      setError(
        requestError instanceof Error
          ? requestError.message
          : "Something went wrong.",
      );
    } finally {
      setLoading(false);
    }
  }

  return (
    <main className="mx-auto max-w-4xl space-y-8 p-6">
      <section>
        <p className="text-sm font-semibold text-blue-700">Opportunity Equity Engine</p>
        <h1 className="text-4xl font-bold">Find opportunities that fit you.</h1>
        <p className="mt-2 text-gray-600">
          Start with a few details. We will show eligible demo opportunities and explain the match.
        </p>
      </section>

      <form onSubmit={getRecommendations} className="grid gap-4 rounded-xl border p-6">
        <label>
          Grade
          <input className="mt-1 block w-full rounded border p-2" value={grade} onChange={(e) => setGrade(e.target.value)} />
        </label>
        <label>
          City or region
          <input className="mt-1 block w-full rounded border p-2" value={location} onChange={(e) => setLocation(e.target.value)} />
        </label>
        <label>
          Interests, separated by commas
          <input className="mt-1 block w-full rounded border p-2" value={interests} onChange={(e) => setInterests(e.target.value)} />
        </label>
        <label>
          Maximum budget
          <input className="mt-1 block w-full rounded border p-2" type="number" min="0" value={maxBudget} onChange={(e) => setMaxBudget(e.target.value)} />
        </label>
        <button className="rounded bg-blue-700 px-4 py-3 font-semibold text-white" disabled={loading}>
          {loading ? "Finding matches..." : "Find opportunities"}
        </button>
      </form>

      {error && <p className="rounded bg-red-50 p-4 text-red-800">{error}</p>}

      <section className="space-y-4" aria-live="polite">
        {results.length === 0 && !loading && !error && (
          <p className="text-gray-600">Enter your profile to see recommendations.</p>
        )}
        {results.map((result) => (
          <article key={result.opportunity.id} className="rounded-xl border p-5 shadow-sm">
            <div className="flex flex-wrap items-start justify-between gap-3">
              <div>
                <h2 className="text-xl font-bold">{result.opportunity.title}</h2>
                <p className="text-gray-600">{result.opportunity.organization} · {result.opportunity.category}</p>
              </div>
              <strong className="rounded-full bg-green-100 px-3 py-1 text-green-800">
                {result.score}/100 match
              </strong>
            </div>
            <p className="mt-3">{result.opportunity.description}</p>
            <p className="mt-3 text-sm">Deadline: {result.opportunity.deadline ?? "Not confirmed"}</p>
            <ul className="mt-3 list-disc pl-5 text-sm">
              {result.reasons.map((reason) => <li key={reason}>{reason}</li>)}
            </ul>
            <div className="mt-4 flex gap-4 text-sm">
              <a className="text-blue-700 underline" href={result.opportunity.application_url} target="_blank">Application</a>
              <a className="text-blue-700 underline" href={result.opportunity.source_url} target="_blank">Source</a>
            </div>
            <p className="mt-3 text-xs text-gray-500">Last verified: {result.opportunity.verified_at}</p>
          </article>
        ))}
      </section>
    </main>
  );
}
```

This is intentionally a simple starting point. Ask the AI assistant to improve the visual design only after the data flow works.

## Step 9 — Add tests before adding more AI

Create at least these test cases:

| Case | Expected result |
|---|---|
| Grade 11, Montreal, AI, budget 300 | AI challenge and research demo are eligible |
| Grade 8, Montreal, AI | Grade 10–11 research demo is not eligible |
| Grade 11, Toronto, AI | Montreal-only opportunity is not eligible |
| Grade 11, Montreal, budget 50 | 100-dollar opportunity is not eligible |
| Grade 11, Montreal, teaching interest | Volunteering demo ranks higher |
| No opportunities returned | Friendly empty state, not a crash |
| Database unavailable | Helpful error message and server log |

If using a test runner, ask the AI assistant to add one test at a time and explain the assertion. A minimal manual test script is acceptable for the first day, but automate the eligibility rules before expanding the data set.

## Step 10 — Add AI explanations only after matching works

The first version can use a template instead of an LLM:

```ts
export function buildExplanation(score: number, reasons: string[]) {
  return `This is a ${score}/100 match because ${reasons.join(" ")}`;
}
```

Later, add an AI explanation route on the server. The LLM may summarize verified facts, but it must not decide whether the student is eligible.

### Safe explanation input

Send only the fields needed for the explanation:

```json
{
  "student": {
    "grade": 11,
    "location": "Montreal",
    "interests": ["AI", "medicine"]
  },
  "opportunity": {
    "title": "Biomedical Research Exploration (Demo)",
    "grades": "10–11",
    "locations": ["Montreal"],
    "cost": 100,
    "source_url": "https://example.com/demo-research"
  },
  "rule_results": {
    "grade": "pass",
    "location": "pass",
    "budget": "pass"
  }
}
```

### Explanation prompt

```text
You explain a verified opportunity recommendation to a high school student.

Use only the supplied facts. Do not invent a deadline, requirement, cost,
organization benefit, or probability of acceptance. If a fact is missing,
say that it is not confirmed. Keep the explanation under 80 words.

Return JSON with exactly:
{
  "explanation": "...",
  "uncertainties": ["..."]
}
```

Validate the JSON, store the model version, and provide a template fallback if the AI request fails. Review the current [OpenAI structured outputs documentation](https://developers.openai.com/api/docs/guides/structured-outputs) when implementing the provider call.

## Step 11 — Add search and filters

After the recommendation flow works, add filters in this order:

1. Category.
2. Location.
3. Maximum cost.
4. Deadline status.
5. Language.

Keep eligibility filters in code or SQL. Do not ask an LLM to filter a list that could be filtered deterministically.

## Step 12 — Add admin review as a controlled workflow

The project needs a way to correct bad data. The first admin workflow can be a protected internal page or a shared review spreadsheet, provided it is not exposed publicly.

Review fields:

- Title and organization.
- Grade range.
- Location.
- Cost.
- Deadline.
- Application URL.
- Source URL.
- Evidence text.
- Verification date.
- Published or needs-review status.

Do not build public admin write access. If authentication is added, require a verified admin role and test the access policy.

## Step 13 — Add embeddings only when keyword matching is insufficient

Embeddings are useful when a student writes “I like health technology” and an opportunity says “biomedical research and machine learning.” They are not required for the first demo.

Add them only after the team has:

- At least 30 verified opportunities.
- A labeled set of relevant and irrelevant examples.
- A working keyword and structured-filter baseline.
- A way to compare whether vector search improves results.

The team should be able to demonstrate that embeddings improve the product rather than adding them because they sound advanced.

## Common beginner mistakes

| Mistake | Better approach |
|---|---|
| Building every feature at once | Build one complete vertical slice |
| Asking AI for a full application in one prompt | Give one small requirement at a time |
| Letting the LLM decide eligibility | Use deterministic code for hard rules |
| Using real data before understanding privacy | Start with fictional or manually verified data |
| Committing `.env.local` | Use environment variables and secret scanning |
| Ignoring errors because the page looks good | Test database, network, validation, and empty states |
| Adding vector search immediately | Prove a keyword/filter baseline first |
| Copying code nobody understands | Ask AI to explain it and have a teammate review it |

## Demo presentation script

Use this sequence for a school presentation:

1. Explain the problem: students miss opportunities because information is scattered.
2. Enter a Grade 11 Montreal student interested in AI and medicine.
3. Show the filtered and ranked results.
4. Open a result and show its reason, deadline, and source link.
5. Change the grade to 8 and show the research opportunity disappear.
6. Change the budget and show a paid opportunity disappear.
7. Explain which parts use AI and which parts use traditional code.
8. Show the test cases and data-review process.
9. Explain one limitation honestly.
10. Describe the next improvement based on pilot feedback.

## Definition of done for the sample demo

The sample implementation is complete when:

- The app runs locally from documented steps.
- A student can submit a profile and receive results.
- The database contains at least three clearly labeled records.
- Grade, location, budget, and interest behavior is understandable.
- Results include a score, reason, deadline status, and source link.
- Invalid input and failed database requests are handled.
- Eligibility logic has tests or a documented manual test script.
- No secrets or private student data are committed.
- A teammate can explain the main files and data flow.
- The team can demonstrate one limitation and one future improvement.

## Final message to the team

Start small enough that you can see the whole system working. Use vibe coding to cross language and framework barriers, but keep your creativity in charge of the product. You are allowed to experiment with the interface, scoring, categories, and user experience. The technical discipline is simply to test your ideas, protect users, verify opportunity information, and improve the product based on evidence.
