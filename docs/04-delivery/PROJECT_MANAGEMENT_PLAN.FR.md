# Moteur d’équité des opportunités — Plan de gestion

## Proposition

En un semestre, l’équipe construira une démonstration ciblée de découverte d’opportunités. La priorité est donnée aux données fiables, à une correspondance claire et à une prochaine étape compréhensible plutôt qu’à une longue liste de fonctions.

## Rôles

Les responsabilités peuvent couvrir le produit et la recherche, le design, les données et la vérification, le front-end, le back-end et l’infrastructure, les tests et la présentation. Une personne peut avoir plusieurs rôles, mais chaque tâche doit avoir un responsable et, si possible, un réviseur.

## Cadence

Commencer par la recherche et la portée, créer un prototype, préparer les données, réaliser le parcours de correspondance, tester avec des utilisateurs, corriger les problèmes prioritaires et préparer la démonstration. Chaque semaine doit produire un résultat vérifiable.

## Outils et collaboration

Utiliser GitHub pour le code et les issues, Markdown pour les décisions, un modèle de données commun et un tableau pour les tâches. Les commits doivent rester petits et les demandes de fusion doivent décrire les changements, les tests et les limites connues.

## Coûts et risques

La première version doit privilégier les services gratuits ou peu coûteux. Les principaux risques sont les données erronées ou périmées, les hallucinations de l’IA, l’élargissement du périmètre, la fuite de données, le manque de temps et les hypothèses non testées. Les réponses sont la vérification des sources, la revue humaine, la collecte minimale, la tranche verticale et les retours réguliers.

## Définition de terminé

Un élève peut créer un profil, obtenir un résultat, comprendre la raison, consulter la source officielle et enregistrer une prochaine action. L’équipe peut présenter les tests, les limites, l’état de vérification des données et le plan suivant.
